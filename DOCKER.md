# Запуск в Docker

```
docker compose up --build
```

Поднимаются PostgreSQL (миграции `0001`, `0002` и тестовые данные из `db/seed.sql`) и приложение на `http://localhost:8080`.
Вместе с HTTP-сервером запускается `BackgroundWorker`, который восстанавливает зависшие операции.
Сбросить данные к исходным: `docker compose down -v`, затем снова `up`.

В PowerShell вместо `curl` пиши `curl.exe`.

## Эндпоинты

- `POST /applications/{id}/block-limit` — заблокировать лимит (`BlockLenderLimit`).
- `GET /applications/{id}` — заявка.
- `GET /operations` — таблица `limit_block_operation`.
- `GET /outbox-events` — таблица `outbox_events`.

## Тестовые данные

ID заявок: `a0000000-0000-0000-0000-0000000000NN`. Поведение учебного кредитора выбирается по последней цифре `lender_id` (см. `internal/fakes/lender.go`).

| Заявка | Кредитор | Что проверяет | Ожидаемый ответ |
|---|---|---|---|
| 01 | блокирует сразу | успех и повтор | 200 `LIMIT_BLOCKED`, одно событие в outbox; повтор тоже 200 без нового события |
| 02 | отказ | отказ кредитора | 422; операция `DECLINED`, заявка остаётся `SCORING_APPROVED`; повтор — 422 без вызова кредитора |
| 03 | блокирует, ответ потерян | ручной повтор | 503, затем повтор → 200 с той же блокировкой |
| 04 | 2 раза недоступен | временная недоступность | 503, 503, на третий раз 200 |
| 05 | зависает | таймаут кредитора | 504 через 3 с, операция остаётся `PENDING` |
| 06 | всегда `unknown` | неизвестный результат | 503, операция остаётся `PENDING` |
| 07 | `confirmed` без номера | нарушение контракта | 503, операция остаётся `PENDING` |
| 08 | отвечает через 2 с | два одновременных вызова | оба 200, одна блокировка, одно событие |
| 13 | блокирует, ответ потерян | фоновое восстановление | 503; через 3–5 минут фон находит блокировку через `LookupBlock` → `LIMIT_BLOCKED` |
| 09 | — | заявка `INITIAL` | 409 |
| 10 | — | уже `LIMIT_BLOCKED` | 200 как есть |
| 11 | — | уже `CONTRACT_SIGNED` | 200 как есть |
| 12 | — | заявка `REJECTED` | 409 |
| 99 | — | нет такой заявки | 404 |

## Примеры

```
curl -X POST http://localhost:8080/applications/a0000000-0000-0000-0000-000000000001/block-limit
curl http://localhost:8080/outbox-events
```

Два одновременных вызова (bash / Git Bash):

```
for i in 1 2; do curl -s -X POST http://localhost:8080/applications/a0000000-0000-0000-0000-000000000008/block-limit & done; wait
```

## Полезное

Логи: `docker compose logs -f app`. SQL-консоль: `docker compose exec db psql -U outbox -d outbox`.

Фоновый обработчик срабатывает раз в 3 минуты и берёт операции, которые не менялись больше 2 минут.
Чтобы не ждать второе условие:

```sql
UPDATE limit_block_operation SET updated_at = now() - interval '10 minutes' WHERE state = 'PENDING';
```

Публикатора outbox в Kafka нет, поэтому `published_at` у событий остаётся пустым.
Учебный кредитор хранит состояние в памяти: после перезапуска приложения он «забывает» выполненные блокировки.
